# Prepare evidence

Prepared 2026-09-26. The fixed corpus contains 112 distinct quartet systems: 12 hand cases and 100 seeded random cases, with 59 YES and 53 NO. There are four to six taxa. Even random seeds select quartets displayed by a planted tree; odd seeds contain two incompatible splits on the same four taxa. `generate_cases.py` fixes inputs and seeds before construction.

Run `uv sync --locked` and `uv run --locked python campaigns/mim-width-one/work/check.py --self-test`. It first runs the copied `research/validate_preparation.py`, regenerates random source systems, recomputes all labels and directly validates tree witnesses. The oracle enumerates all unrooted binary labelled trees by repeatedly subdividing every possible edge to insert the next leaf; counts 1, 1, 3, 15 and 105 for two through six leaves match the known double-factorial counts. Quartet display is checked by explicit tree-edge splits. For the target, each split is checked for a pair of independent crossing edges with no cross-edge between their four endpoints. This is exactly an induced matching of size two, so full tree enumeration conclusively decides width at most one on the finite tested domain. Among 100 seeded target graphs with two to six vertices, 99 were YES and one was NO; the latter is retained as a hand fixture. Hand source fixtures include contradictory quartet splits. An intentionally incorrect candidate returning an empty graph and always extracting NO-SOLUTION was rejected.

Oracle: CPython 3.12.14, standard library only, locked with `uv.lock`. Enumeration grows superexponentially and finite evidence covers at most six leaves. The candidate gate checks at most three target decomposition trees per source case, not every target output. No reduction or solution is claimed.
